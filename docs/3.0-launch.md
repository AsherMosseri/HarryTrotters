# 3.0 launch steps

From the launch practice run (Oct 31). Server code and rules deploy only from
`main`, so everything below goes live together when `redesign` is merged.

## Before
1. Pick a quiet time with no lab session.
2. Set the launch day (team day, New York) in two places:
   - `RATES_FROM` in `functions/shared/coins.js` (3.0's coin rules start that day; earlier lab time keeps 2.75's rate).
   - `DAILY_FROM` in `functions/shared/bingo.js` can stay at 2026-11-09 for a Nov 2–3 launch.
   - The 3.0 `date` in `src/changelog.js`.
3. On the Roster, fix anyone listed under two spellings (for example "katarina jurasic" and "Katarina Jurasic"): rename one into the other.
4. GitHub → Settings → Secrets → Actions has `FTC_API_USER` and `FTC_API_KEY`.
5. Tell the team when it's happening. iPhone/iPad people make their password on the old app's "Get the new app" screen; anyone who skips it needs the team code once in the new app.

## Launch
1. Merge `redesign` into `main` (a fast-forward). Two workflows start:
   - Deploy to GitHub Pages (about 3–5 minutes).
   - Deploy rules and notifications (about 10–20 minutes): secrets, then the functions (27 new), then the rules. If the functions step fails, re-run failed jobs; the old rules stay live until it succeeds.
2. Asher on the iPad: the old app shows Get the new app → make your password → Safari → Add to Home Screen → pick your name and type it.
3. Check (just looking): Cloud Scheduler lists the new `firebase-schedule-*` jobs (bingoSweep, lockPredictions, payTournaments, postDailyQuestion, weeklyRecap) in America/New_York; Secret Manager has the two FTC secrets; logs show no "requires an index" errors on day one; on Today, pulling the schedule from FTC Events works.
4. Look over coin balances for anyone negative.

## Rollback
1. Firebase console → Firestore → Rules → history: restore the version from before launch; same under Storage → Rules. Do this first.
2. Revert the merge on `main`. Pages rebuilds 2.75 and the workflow redeploys 2.75's functions.
3. Coins earned through 3.0 awards and refunds don't count under 2.75; Market purchases still subtract.

## Offline copy
The app saves a copy of itself on each device (a service worker, `public/sw.js`), so after one online visit it opens with no internet, and the data it already loaded (schedule, checklists, Today, tasks, match log, roster, chat, lab log) stays readable. Things people change offline wait on the device and send by themselves when the internet is back; a small "Offline — changes will sync" pill says so, then "Back online". Things that need the server (coins, games, Market, guesses, signing in for the first time) say "Needs internet".

**Before the event (Nov 14)**
1. Everyone opens the app once on good Wi-Fi after launch. On iPhone/iPad the Home Screen app is its own copy: open the Home Screen app itself (not Safari), wait a few seconds on Today.
2. Check it: on the iPad, turn on Airplane Mode, close the app, open it again. It should open on Today with the pit screen and the data, and show the Offline pill.
3. A device that has never signed in needs internet once (it says so). Sign in on every phone and tablet before the venue.

**How updates still work.** The page itself (index.html) is always fetched from the network first, and the saved copy is only used when there's no connection (or it takes over 5 seconds). The code files have new names every build, so a deploy never serves old code. Each build saves into its own cache named by the build id, and older caches are deleted when the new worker takes over. version.json, offline.json and sw.js are never served from the copy, so "Update now" and the update pill work as before. A half-published deploy can't break a phone: if a new copy fails to save, the working one stays until it can.

**Kill switch.** If the offline copy ever misbehaves:
1. Set `public/offline.json` to `{ "enabled": false }` and merge to `main` (for the test copy, to `redesign`). When Pages has deployed, each phone that opens the app (online) clears its saved copy and the worker removes itself, unless that phone has notifications on, then it stays as a notification-only worker that saves nothing. The worker also looks at the switch whenever the app is opened or reloaded (at most once a minute).
2. Set it back to `{ "enabled": true }` to turn the offline copy on again; phones save a new copy on their next visit.
3. If the worker itself is broken so badly that step 1 can't reach it, replace `public/sw.js` with this and deploy (no markers in it means the build leaves it alone):
   ```js
   self.addEventListener('install', () => self.skipWaiting());
   self.addEventListener('activate', (e) =>
     e.waitUntil(caches.keys().then((ks) => Promise.all(ks.map((k) => caches.delete(k)))).then(() => self.registration.unregister())));
   ```
   Phones pick it up the next time they open the app online (the browser re-reads sw.js on every launch and at least once a day).

Rolling back 3.0 is safe: 2.75's worker saves nothing and passes everything through. A few MB of old saved files stay on devices, unused.

The redesign test copy (`/next/`) has its own worker and copy, separate from the team's app.
